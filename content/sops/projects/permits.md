# Permits & Inspections

| | |
|---|---|
| **Purpose** | Permitted work is filed before the crew rolls, and the inspection is closed out rather than forgotten. |
| **When it applies** | Every project. Even the ones that turn out not to need one — the decision is recorded either way. |
| **Owner** | Project Manager. |

## Decide, and write it down {#decision}

Every project gets one of two notes on the job:

- `PERMIT FILED — [municipality] — [permit #] — [date]`
- `NO PERMIT REQUIRED — [municipality] — confirmed with [name/source] on [date]`

An empty permit field is not "no permit needed". It is an unanswered question, and it becomes the homeowner's problem at closing when they sell the house.

## Typical triggers {#triggers}

Requirements vary by town across Nassau and Suffolk — confirm with the municipality, never assume from the last job:

- Equipment replacement with gas or oil piping changes
- New electrical circuits or service changes
- New ductwork or venting penetrations
- Any new system where none existed
- Most commercial rooftop work

## File before the install date is promised {#sequence}

Where a permit is required and the town will not allow work before issuance, the install date is set **from the permit**, not from equipment delivery. Tell the customer the honest sequence up front: "Your town requires a permit; that's typically [x] days. I'll book your install the day it's issued."

## Inspection {#inspection}

- Schedule the inspection at install completion, not weeks later.
- The lead installer's startup documentation is what the inspector reads — see `sop.projects.install-day`.
- If an inspection fails, we correct it at our cost and re-inspect within five business days. The customer is told the same day, by us.
- The project is not closed until the inspection passes — see `sop.projects.closeout`.
